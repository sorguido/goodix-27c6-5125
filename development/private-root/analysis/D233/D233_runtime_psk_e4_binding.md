# D233 runtime PSK ↔ E4 binding closure

`RuntimePskE4Binder.from_canonical_pe()` now binds the runtime gate to the
recovered D190 reference. Before any backend is constructed, the orchestrator
hash-gates the PE and requires its bounded target pattern to be unique. At E4
the binder re-derives (it does not cache) validator[32] from the same owned
`SecretBuffer` later passed by identity to `Tls12PskServer`.

The gate requires typed response `bb020003`, length 32, and compares with
`hmac.compare_digest`. Mismatch is `secret_boundary_failure` after the single E4
request and before A2. The mutable expected validator and all mutable reference
intermediates are overwritten. There is no historical MATCH shortcut,
hardcoded primary validator, alternate PSK, fallback, random branch or retry.

## Non-circular evidence

The expected V0–V4 validators were recovered from the D190 session that records
their production by the OEM machine-code oracle and two independent clean-room
models before they were added to the reference self-test. The restored reference
then reproduced those pre-existing values from the canonical local PE. Thus the
expected values were not generated by the function under this test.
